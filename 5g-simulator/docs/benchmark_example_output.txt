KEY TAKEAWAY:
  Throughput gap: ~1x (both fast in-process simulation)
  Latency gap:   ~1,800x at p50 (327μs vs 167ns)

  The throughput gap is small here because both paths share the same
  process and hash-map lookups dominate. In production:
    - Socket/kernel UPF:  0.2–1 Mpps per core
    - DPDK UPF:           10–40 Mpps per core
  The latency gap is REAL even in simulation:
    condition_variable wake latency (~300μs) vs lock-free poll (~167ns).
