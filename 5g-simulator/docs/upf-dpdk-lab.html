in a production DPDK UPF

rte_eth_rx_burst()

Replaces our SPSCRing::pop_burst(). The NIC PMD (mlx5, i40e, dpaa2) reads hardware DMA descriptor rings. Packet arrives from wire → mbuf in one step, no interrupt, no syscall, no kernel.

Hugepages (2MB / 1GB)

DPDK's mempool is backed by /dev/hugepages. 2MB pages reduce TLB misses by 512× vs default 4KB. At 10Mpps, 4KB pages would thrash the TLB; 2MB pages need ~1 entry for the entire mbuf pool region.

VFIO / UIO

The NIC PCI device is remapped to userspace via vfio-pci. The kernel driver is unloaded. The application has direct memory-mapped access to NIC registers and DMA rings — no driver stack in the path.

NUMA Pinning

Each lcore is pinned to the same NUMA socket as its NIC. rte_socket_id() routes mbuf allocations to local DRAM. Cross-NUMA memory access costs ~100ns and halves effective memory bandwidth.

RSS Multi-Queue

NIC hashes flows (TEID or 5-tuple) across N RX queues. Each queue is owned by one lcore. Linear scaling: 4 lcores ≈ 4× throughput. Packets from the same UE always go to the same lcore — preserving order, keeping PDR cache hot.

RCU Rule Updates

When SMF sends a PFCP Session Modification (e.g. handover TEID change), the fast-path PDR table must update without stalling the lcore. Production UPFs use Read-Copy-Update (RCU) or version-epoch per-lcore caches.
